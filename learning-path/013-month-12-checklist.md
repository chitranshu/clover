# Month 12 (Day 1–Day 30) — Final Capstone + Portfolio + Interview Readiness

_Last updated: 23 Feb 2026_

## How to use this checklist
- Target: **2 to 3 hours/day**.
- Focus: one polished end-to-end project + strong storytelling.
- Prioritize clarity, reproducibility, and demonstrable impact.

---

## Week 1 (Days 1–7): Problem Selection + Scope Lock

### Day 1
- [ ] Choose final capstone domain and user/problem statement
- [ ] Define target users and success metric
- [ ] List constraints (data, latency, cost, privacy)
- [ ] Notes: why this project matters

### Day 2
- [ ] Select dataset(s) and verify legal/ethical usage
- [ ] Conduct quick data quality audit
- [ ] Confirm feasibility within time budget
- [ ] Document assumptions and non-goals

### Day 3
- [ ] Draft end-to-end system architecture
- [ ] Define modules: data, model, serving, monitoring
- [ ] Choose tech stack and toolchain
- [ ] Create milestone plan

### Day 4
- [ ] Build repo skeleton (`src`, `notebooks`, `app`, `tests`, `docs`)
- [ ] Add coding standards and contribution notes
- [ ] Add reproducible environment setup
- [ ] Initialize project board/checklist

### Day 5
- [ ] Implement baseline pipeline and first metric run
- [ ] Validate train/val/test protocol
- [ ] Save baseline artifacts and report
- [ ] Identify top improvement opportunities

### Day 6
- [ ] Define experiment tracking and versioning strategy
- [ ] Add model/artifact naming conventions
- [ ] Add risk register (technical + ethical)
- [ ] Write project README first draft

### Day 7 (Review)
- [ ] Confirm scope lock and acceptance criteria
- [ ] Week summary (1 page)
- [ ] Push baseline milestone
- [ ] Finalize week-2 build priorities

**Week 1 Deliverable**
- [ ] Scope-locked capstone with baseline pipeline and architecture

---

## Week 2 (Days 8–14): Build and Improve the Core System

### Day 8
- [ ] Implement improved model/pipeline iteration #1
- [ ] Compare with baseline on fixed protocol
- [ ] Log gains and side effects
- [ ] Update experiment table

### Day 9
- [ ] Implement iteration #2 focused on biggest bottleneck
- [ ] Run controlled ablation
- [ ] Validate improvements are real
- [ ] Document rationale

### Day 10
- [ ] Add robust evaluation (slice-based/per-class/task-specific)
- [ ] Build error analysis notebook
- [ ] Identify persistent failure modes
- [ ] Draft mitigation actions

### Day 11
- [ ] Add explainability/reporting where relevant
- [ ] Validate explanations against domain logic
- [ ] Highlight uncertain predictions or weak confidence
- [ ] Update risk section

### Day 12
- [ ] Add inference layer (CLI/API/app endpoint)
- [ ] Validate input schema and failure handling
- [ ] Benchmark latency and resource usage
- [ ] Document usage examples

### Day 13
- [ ] Add logging/monitoring hooks (basic)
- [ ] Track key runtime and quality metrics
- [ ] Add drift/data quality notes if applicable
- [ ] Save operations checklist

### Day 14 (Review)
- [ ] Re-run best pipeline from clean environment
- [ ] Week summary (1 page)
- [ ] Push milestone
- [ ] Freeze candidate architecture

**Week 2 Deliverable**
- [ ] Strong candidate system with validated improvements

---

## Week 3 (Days 15–21): Productization + Documentation Excellence

### Day 15
- [ ] Harden code quality (lint, tests, type checks as applicable)
- [ ] Add unit/integration tests for critical paths
- [ ] Ensure reproducible seed/config behavior
- [ ] Fix high-priority technical debt

### Day 16
- [ ] Containerize project or create one-command setup
- [ ] Validate setup on a clean machine/environment
- [ ] Add troubleshooting section
- [ ] Document known limitations

### Day 17
- [ ] Build concise architecture diagram and data flow
- [ ] Add model lifecycle diagram (train → deploy → monitor)
- [ ] Embed diagrams in docs
- [ ] Review clarity for external readers

### Day 18
- [ ] Write polished README (problem, setup, results, usage)
- [ ] Add benchmark/results table
- [ ] Add ablation and error analysis summaries
- [ ] Add future work roadmap

### Day 19
- [ ] Prepare short technical report (2–5 pages)
- [ ] Include risks, ethics, and governance notes
- [ ] Add assumptions and decision log
- [ ] Validate claims with reproducible evidence

### Day 20
- [ ] Prepare project demo script (narrative and steps)
- [ ] Rehearse timing and flow
- [ ] Capture screenshots/videos as needed
- [ ] Refine based on dry run

### Day 21 (Review)
- [ ] Complete docs quality audit
- [ ] Week summary (1 page)
- [ ] Push release candidate
- [ ] Resolve final high-impact issues

**Week 3 Deliverable**
- [ ] Production-quality documentation + reproducible project package

---

## Week 4 (Days 22–30): Portfolio Packaging + Interview Readiness

### Day 22
- [ ] Finalize capstone metrics and acceptance checks
- [ ] Freeze final model/service versions
- [ ] Tag stable release
- [ ] Prepare final artifact bundle

### Day 23
- [ ] Write portfolio case study (problem → approach → impact)
- [ ] Add key visuals and result highlights
- [ ] Publish in `docs/` or personal blog
- [ ] Link all artifacts clearly

### Day 24
- [ ] Create one-page project brief (recruiter-friendly)
- [ ] Emphasize outcomes, constraints, and tradeoffs
- [ ] Add concise tech stack summary
- [ ] Validate readability

### Day 25
- [ ] Prepare interview Q&A bank (20–30 questions)
- [ ] Cover design choices, failures, and lessons
- [ ] Write STAR-style responses for challenges
- [ ] Practice concise explanations

### Day 26
- [ ] Mock interview session (self or peer)
- [ ] Practice whiteboard/system design explanation
- [ ] Identify weak answers and improve them
- [ ] Record revision notes

### Day 27
- [ ] Final polish pass on repo/docs/demo assets
- [ ] Verify all links, commands, and outputs
- [ ] Clean obsolete files
- [ ] Confirm reproducibility one last time

### Day 28
- [ ] Publish final demo video (optional)
- [ ] Share capstone publicly (GitHub/post/community)
- [ ] Collect final feedback
- [ ] Apply any critical fixes

### Day 29
- [ ] Write Year 1 AI learning retrospective
- [ ] Summarize strengths, gaps, and Year 2 goals
- [ ] Define next specialization path
- [ ] Create follow-up 90-day plan

### Day 30 (Final Demo Day)
- [ ] Deliver Month 12 capstone package:
  - [ ] End-to-end AI system with evidence-backed results
  - [ ] Reproducible setup/deploy/infer workflow
  - [ ] Strong docs, report, and demo narrative
  - [ ] Portfolio-ready case study
- [ ] Celebrate completion of Year 1 roadmap

**Month 12 Completion Criteria**
- [ ] One polished end-to-end project ready for portfolio review
- [ ] Clear technical communication (README, report, demo)
- [ ] Interview-ready discussion of tradeoffs and limitations
- [ ] Concrete Year 2 specialization plan
